# Upgrade an existing alpha.8 installation to alpha.9

Use this procedure for an existing alpha.8 installation. Keep the event unpublished and preserve its current website path, public connection values, Auth redirects, private pictures and server settings. The fresh installer is for an empty application schema.

1. Download a Full application backup. Keep separate protected recovery copies of PostgreSQL, Supabase Auth/Storage, Edge Function settings and website configuration. Application backups do not replace those recovery copies.
2. Review and rehearse the [scoped alpha.8 to alpha.9 SQL](../supabase/upgrades/alpha8-to-alpha9.sql) on a disposable alpha.8 database. After verifying the backup and source schema, run the scoped upgrade on the destination with the database owner. It adds template language tags and guarded service/language matching, and updates the private label registry. It must preserve existing event records, template wording/pictures, access and unpublished state. Do not replay `supabase/install.sql` over an installed event.
3. If you use experimental Apple Shortcuts, deploy its release-matched `invitation-shortcuts` function and preserve the existing secrets, origin/site URL, JWT-verification settings and Auth redirects. Its changed entrypoint supports explicitly configured local transport; ordinary guest-gateway and administrator-invitation handler logic is unchanged. Keep Shortcuts disabled unless separately enabled for supervised testing. [Studio guide](StudioSetup.md)
4. Deploy the alpha.9 website to the existing installation path while retaining its public connection configuration. Check administrator sign-in, households, invitation history, languages and pictures. Main opens **Invites**; its Service chip copies the number/email, and Draft/Ready copies the saved invitation. Verify the separate Rows defaults and mandatory columns. Picture-and-text paste needs a receiving-app check; Text copies the original invitation message as a fallback.
5. Open the existing named templates and review their **Language tags**. Existing templates appear untagged; the upgrade does not assign languages, guess matches or create drafts. Assign the intended household languages and verify that each service/language pair has exactly one eligible template before using **Generate Drafts**. Existing drafts, template wording and pictures remain retained.
6. Download a fresh Full backup after upgrading and rehearse restore on disposable data. The template column contract expands even though backup format 2/schema `20261114034908` and the 43-table count stay the same. Keep the pre-upgrade Full backup for recovery of alpha.8, and use a newly exported alpha.9 Full backup for alpha.9 restore tests. Keep event publication a separate explicit decision.
