Install with local Supabase

Use your own computer or VM, a container runtime and the Supabase CLI. Keep the website, database baseline and Edge Functions from the same RSVP Manager release.

1. Start the local stack

From your configured Supabase project directory:

supabase start
supabase status

Use the Studio and API URLs printed by the CLI. When opening the website from another device, use the VM’s hostname instead of localhost. Copy only the public/publishable or anon browser key; keep secret/service keys private. If the website uses HTTPS, its API must use HTTPS too.

2. Install the current schema once

Starting the stack from this release’s project directory applies its single baseline automatically. If that happened, skip SQL installation. If the application schema is empty, open local Studio → SQL Editor and run the complete SQL installer once. The wizard never executes privileged SQL. Do not run the installer over an installed event or apply both installation routes.

In local Studio → Authentication → Users, create and confirm the first Auth user. The wizard generates the separate SQL to grant first-administrator access.

3. Run the Edge Functions locally

If both functions are already running under your VM’s configured service, keep that setup. Otherwise, use the release’s complete supabase/functions directory and supabase/config.toml. Put these environment entries in a private file outside the served website; replace the example URLs with the actual website origin and installation URL: 

RSVP_SITE_ORIGIN=http://localhost:8080
RSVP_SITE_URL=http://localhost:8080/

The origin has no path or trailing slash; the site URL includes its installation path and trailing slash. From the same Supabase project directory, run: 

supabase functions serve --env-file /private/path/rsvp-functions.env --no-verify-jwt

Keep it running while testing, or manage it through your local service. Both guest-gateway and admin-invitations must use the same website settings. Their invitation-code, origin, rate-limit and administrator/session validation stays enabled. Never place server credentials in browser files.

4. Complete the wizard

Under local Studio → Authentication → URL Configuration, set the full website Site URL and allow its admin/?admin-invitation=1 redirect. Return to the wizard, enter the API URL and public browser key, and choose Test connection. Verify the administrator, then install the downloaded config.js as js/config.js in your local website directory. Existing VM installations may already have their public configuration in place.

Keep the event unpublished while testing. Cloud installations use the cloud Studio guide instead.
