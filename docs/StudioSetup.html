Install RSVP Manager through Supabase Studio

In Supabase Studio, select your project. These steps run entirely in your browser. The two paste-ready files below match your selected release.

Run the complete install.sql once on your new empty project first. If the SQL stage is already complete, continue with the functions. Keep the event unpublished.

Cloud project security options

When creating the project, expand Security options and select:

Setting Choose Reason
Enable Data API ON Required for the website and Edge Function database calls.
Automatically expose new tables OFF The installer supplies explicit permissions.
Enable automatic RLS ON Protects future tables; the installer also enables RLS and creates the application policies.

Keep public in the Data API exposed schemas. Do not expose app_private. For an existing project, check Data API availability and exposed schemas under Integrations → Data API. These switches do not publish an event. Local installations use the local setup guide.

Wizard order

  1. Step 1: choose New database → Cloud for a fresh project, or Existing database for an installed event.
  2. Step 2: install SQL once if empty, save site secrets, deploy both functions and configure Auth URLs. Then press Test connection.
  3. Step 3: create/confirm the first Auth user, grant first-administrator access and verify login.
  4. Step 4: publish the browser configuration through GitHub Actions variables or a direct config.js upload.

The wizard temporarily configures this browser for its tests. Actions variables configure the deployed website for all visitors; they do not set Supabase secrets or deploy functions.

0. Install SQL on a fresh project

In wizard step 2, download the complete SQL installer and run it once in the project’s SQL Editor if the application schema is empty. Skip this on an installed event. The wizard does not execute SQL or reset a database.

1. Save the site secrets

Open Edge Functions → Secrets, add these entries and Save:

Name Value
RSVP_SITE_ORIGIN https://events.example.org
RSVP_SITE_URL https://events.example.org/

Supabase supplies its server credentials automatically. Only the site settings above need adding here.

2. Deploy guest-gateway

  1. Open Edge Functions → Deploy a new function → Via Editor.
  2. Name it exactly guest-gateway.
  3. Replace the template's entire index.ts with the complete file below.
  4. Click Deploy function.
  5. In its Details tab, turn Verify JWT (or Verify JWT with legacy secret) OFF and save. Select OFF at initial deployment too if offered.

3. Deploy admin-invitations

Repeat those steps with the exact name admin-invitations and this file. Turn its platform Verify JWT OFF too.

admin-invitations: complete index.ts Download file

Checking the code files…

These files include the shared helpers. Guest invitation validation and administrator authentication/permissions remain enforced by the handlers.

4. Configure Auth URLs before the connection test

Under Authentication → URL Configuration, set Site URL to https://events.example.org/ and allow https://events.example.org/admin/?admin-invitation=1. Configure these URLs before creating or inviting the first Auth user. Configure email/SMTP for actual invitation delivery.

5. Verify the functions, then Test connection

In guest-gateway → Test, send POST with headers Origin: https://events.example.org and Content-Type: application/json, and: 

{"action":"get_invitation_v2","args":{"p_code":"AAAAAAAA"}}

A fresh unpublished event returns 200 with JSON null. A POST of {} to admin-invitations without a signed-in administrator JWT returns 401 from its handler and sends no email. Return to the wizard and retry Test connection.

6. Wizard steps 3 and 4

After Test connection succeeds, follow wizard step 3 to create/confirm the first Auth user and grant first-administrator access. Existing installations use their existing administrator. Step 4 then configures the deployed website for everyone.

Browser-local setup applies only to that browser. For all visitors, open Settings → Secrets and variables → Actions → Variables in your website repository and create RSVP_SUPABASE_URL and RSVP_PUBLISHABLE_KEY, then rerun its deployment workflow. Copy supabaseUrl and supabaseKey from the downloaded config without JavaScript quotes. The workflow generates js/config.js in the Pages artifact; uploading a separate file to the website repository does not configure it. Use only public project connection values.

Keep the event unpublished until launch is deliberately approved.
