New database instructions
  1. Create a cloud Supabase project

  2. In the cloud project’s Security options, choose:

    • Enable Data API: ON

      Required for the website and Edge Function database calls.

    • Automatically expose new tables: OFF

      The installer grants only the access this application needs.

    • Enable automatic RLS: ON

      Keep this protection enabled. The installer also enables RLS and supplies the application policies.

    Keep public in the Data API exposed schemas. Do not expose app_private.

  3. Open its SQL Editor and run the complete downloaded installer once on the empty application schema.

Put your configuration online

Administrator verified. Your website configuration is ready.

GitHub Pages — selected-release workflow

  1. In the website repository, open Settings → Secrets and variables → Actions → Variables. Add repository variables, not secrets.
  2. Set RSVP_SUPABASE_URL to the Project URL used in step 2 and RSVP_PUBLISHABLE_KEY to its public browser key. Enter values without JavaScript quotes.
  3. Open Actions → Deploy RSVP → Run workflow, select the installed release and run it. Wait for the deployment to succeed.
  4. Open the website in a private browser window to verify sign-in and Guest preview with the deployed configuration.

The workflow generates js/config.js. Uploading a downloaded config.js to the repository does not configure the Pages artifact. No configuration file upload is needed for this workflow.

Direct static hosting

Download config.js and upload it as js/config.js in the website installation directory. Browser-only setup configures this browser, not other visitors.

The file contains only your Supabase URL and publishable / anon key. It must not contain a secret or service_role key.

Verify sign-in and Guest preview on the hosted site. Test a published guest journey in a separate installation with synthetic records. Keep the real event unpublished until launch is approved.
